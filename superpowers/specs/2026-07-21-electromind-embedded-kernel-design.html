ElectroMind 独立产品与内置派生内核设计 ​

决策 ​

ElectroMind 是独立产品，并在同一仓库中拥有、维护和发布自己的 Agent 内核。该内核 初始实现由 pagent v4 演化而来，迁入后属于 ElectroMind 源码，不再作为运行时外部 依赖，也不再以 pagent 或 pagentv4 作为 Python 包、CLI、配置、状态目录或用户界面 名称。

用户已经确认拥有复制、修改、重命名和分发 pagent 源码的权利或明确授权。仓库仍需 记录来源和迁移基线，以便工程审计和后续差异追踪。

产品定位 ​

ElectroMind 是面向科学计算和机器学习势函数工作流的通用 Agent 产品：

  • 通用内核负责模型交互、Agent loop、上下文、工具、审批、会话、Sandbox 和 Skills；
  • ai2-kit、Packmol、DeepMD 等领域知识由用户维护的 Skills 提供；
  • Local、Docker 和 SSH 提供交互式执行环境；
  • HPC/Slurm 提供异步批作业生命周期；
  • 产品层提供 ElectroMind CLI、配置、诊断、日志和用户体验。

ai2-kit 与 Docker/SSH/HPC 不属于同一层：前者是领域工作流，后者是执行基础设施。

来源基线 ​

派生内核固定来源为当前仓库 Git 历史中的：

  • upstream repository：git@github.com:SyncLionPaw/pagent.git；
  • commit：ceba69b2e6e5eea99a0da3e9c3b573e6b1297d11；
  • repository tag：v0.7.11；
  • package metadata version：0.7.10；
  • source scope：src/pagentv4/ 的 56 个文件；
  • test scope：23 个 tests/test_pagentv4_*.py 测试文件。

pagent v4 源码不依赖旧 src/pagent/ 或产品 src/app/，因此旧内核和旧产品层均不进入 ElectroMind 内核。原 src/app/ 只作为行为参考；ElectroMind 产品入口按自己的配置、 路径和文案重建。

仓库新增 NOTICE.md，记录上述来源、迁移日期和授权已由项目所有者确认。没有得到用户 明确选择前，不擅自为 ElectroMind 指定开源许可证。公开发布前，用户需要单独确定 ElectroMind 的分发许可条款。

内核迁移映射 ​

第一阶段以行为等价迁移为主，不同时重写 Agent loop：

pagent v4 来源ElectroMind 目标处理
pagentv4/coreelectromind/kernel/core保留模型、事件、工具与 AgentCore
pagentv4/runtimeelectromind/kernel/runtime保留 Runner、loop、hooks、inbound
pagentv4/conversationelectromind/kernel/conversation保留 JSONL/SQLite 会话存储
pagentv4/ithreadelectromind/kernel/threads重命名并保留 ThreadSpec/IThread
pagentv4/skillselectromind/kernel/skills保留渐进式 Skill 加载
pagentv4/toolselectromind/kernel/tools保留通用工具，清理产品文案
pagentv4/sandboxelectromind/execution/sandbox作为执行基础设施而非 core 子包
pagentv4/adapterselectromind/kernel/adapters保留协议适配器
pagentv4/traceelectromind/kernel/trace保留 trace 与导出能力
pagentv4/paths.pyelectromind/kernel/paths.py全部改为 ElectroMind 路径
pagentv4/__init__.pyelectromind/kernel/facade.py建立受控内核公开门面

pagentv4/core/provider.py 在行为等价迁移时先保留原位；对应测试通过后，再单独把 ProviderProtocol 留在 core，并将 OpenAI-compatible 的具体 provider 移到 electromind/providers/openai_compatible.py。该拆分不得与初次 import 改写混在同一 提交中。

迁移采用机械包路径替换和小步提交。每迁移一个模块族，先迁移对应测试并确保通过，再 继续下一个模块族。禁止在同一提交中同时做大规模路径迁移、行为重写和新功能开发。

Python 包与公开入口 ​

pyproject.toml 改为可安装的独立应用：

  • distribution：electromind；
  • import package：electromind；
  • product version：0.1.0；
  • Python：3.11 或更高；
  • console script：electromind = "electromind.app.cli:main"；
  • build backend：uv_build；
  • module name：["electromind"]；
  • 不依赖 pagent；
  • 直接声明派生内核所需的 asyncssh、ddgs、docstring-parser、openai、 prompt-toolkit、pyyaml 和 tiktoken 等依赖。

顶层 electromind/__init__.py 只暴露稳定的产品版本和少量公共 API。内核高级 API 通过 electromind.kernel 的 facade 暴露；内部深层模块不承诺跨版本稳定。

仓库内不得再存在可 import 的 pagent、pagentv4 或顶层 app 包。来源名称只允许 出现在 NOTICE、迁移设计、Git 历史和必要的来源审计测试中。

产品层 ​

ElectroMind 产品层拥有自己的：

  • CLI 与帮助文本；
  • banner、提示符、错误和日志；
  • 配置加载与环境变量；
  • 用户级和项目级状态目录；
  • 诊断命令与版本信息；
  • REPL 命令和工具审批交互；
  • README、发布版本和支持边界。

第一阶段 CLI：

bash
electromind run [--config PATH] [--project PATH] [--thread ID]
electromind doctor [--config PATH]
electromind skills list [--config PATH]
electromind threads list
electromind version

run 直接调用仓库内置内核，不启动子进程或转发到旧 pagent CLI。doctor 不调用 LLM，负责检查配置、Key、Skill、Docker、SSH 和可写目录。用户可见异常必须映射成 ElectroMind 错误，不能残留 pagent 文案。

配置与状态 ​

配置文件为 electromind.toml。加载优先级由低到高为：

  1. 内置默认值；
  2. ~/.config/electromind/config.toml；
  3. 项目根 electromind.toml；
  4. 显式 --config；
  5. CLI 参数。

仓库提交 electromind.example.toml，真实配置被忽略。API Key 只从 ELECTROMIND_API_KEY 或 provider 专用环境变量读取，不写入 example config。旧 DEEPSEEK_API_KEY 可以在一次迁移版本中带警告兼容，但不读取 pagent.toml。

路径统一为：

  • 用户配置：~/.config/electromind/；
  • 用户状态：~/.local/share/electromind/；
  • 项目状态：<project>/.electromind/；
  • 项目 Skills：<project>/skills/；
  • 用户 Skills：~/.config/electromind/skills/；
  • threads：生效状态根下的 threads/。

内核路径解析不得读取或创建 .pagent、~/.pagent、PAGENT_HOME 或 pagent.toml。路径行为由迁移后的专门测试锁定。

Agent 内核边界 ​

内核公开能力由 kernel/facade.py 统一导出：

  • AgentCore、ProviderProtocol、Message、Event、Tool；
  • Runner、RunState、ToolHooks、inbound control；
  • Thread、ThreadSpec、ConversationStore；
  • SkillRegistry 与 use_skill；
  • Sandbox protocol 与受控执行工具。

core 不依赖 app、具体 Sandbox backend、HPC、配置文件或用户界面。runtime 负责编排 core、conversation、thread、skills 和执行协议。app 只使用 facade，不从内核深路径 拼装私有对象。

第一阶段保留 pagent v4 已有的事件循环、消息模型、会话持久化、工具 hooks、取消与 steer 行为。上下文压缩、任务恢复和并行工具属于后续增强，不能混入身份迁移提交。

Skills 与 ai2-kit ​

Skills 是领域能力入口。ElectroMind 内核只定义发现、渐进加载、资源安装和 use_skill 契约，不理解 ai2-kit 训练语义。

每个 Skill 目录至少包含 SKILL.md，可附带 scripts/、references/、assets/ 和 templates/。路径必须同时适用于 Local、Docker 和远端 workspace。

当前整改只保留通用 fixture Skill 验证内核能力，不代替用户编写 ai2-kit Skill。 后续 ai2-kit Skill 负责：准备数据、生成配置、提交任务、检查收敛、选择模型、收集 产物和给出下一步建议。它通过公开工具使用执行层，不直接 import 内核内部模块。

Sandbox 与 HPC 分层 ​

Sandbox 面向交互式、短生命周期操作：文件读写、命令执行、workspace 和 Skill 安装。 迁移保留 Local、Docker、Podman、SSH backend，并将其放在 electromind.execution.sandbox。

HPC/Slurm 面向异步、长生命周期批作业，不能伪装成一次 SSH shell 命令。后续 execution.jobs 提供独立协议：

  • submit(spec) -> JobHandle；
  • status(job_id) -> JobStatus；
  • logs(job_id, cursor) -> LogChunk；
  • cancel(job_id)；
  • collect(job_id, destination)。

Slurm backend 可以复用 SSH 连接作为传输，但拥有自己的 job ID、状态机、重连、日志 游标和产物语义。Agent 工具只调用 JobExecutor 协议；ai2-kit Skill 描述何时调用与如何 解释结果。

本次基础整改迁移 Sandbox 并预留 jobs 的 protocol/models，不实现真实 Slurm 提交。 Slurm 实现作为独立后续里程碑交付。

Docker ​

containers/base/Containerfile 使用 python:3.12-slim-bookworm，安装 bash、 ca-certificates、curl、git 和基础文件工具，镜像名为 electromind-base:0.1。正式发布 前锁定 base image digest。

基础镜像不包含 Key、用户配置、用户数据或领域软件。Packmol、ai2-kit、DeepMD 等使用 独立领域镜像，避免通用 Agent 镜像膨胀和依赖冲突。

审批与安全 ​

工具审批保留 pagent v4 ToolHooks 的能力，但产品策略由 ElectroMind app 提供：

  • 默认 prompt；
  • 只读工具可按明确白名单自动批准；
  • 写文件、执行命令、网络、容器、SSH 和 HPC 提交必须匹配策略；
  • 拒绝与取消必须进入事件和审计日志；
  • 不允许 Skill 自行绕过审批层。

安全整改包括：

  1. 撤销并轮换此前本地配置中出现过的 DeepSeek Key；
  2. 忽略 electromind.toml、.env、.electromind/ 和运行产物；
  3. 扫描受版本控制的配置、脚本和文档，拒绝非空密钥；
  4. 日志和异常不得输出 Key 或 Authorization header；
  5. make audit 执行 uv run pip-audit，任何已知漏洞默认阻断发布；
  6. 漏洞例外必须记录漏洞 ID、影响、缓解措施和复查日期；
  7. 删除旧 VitePress、Electron、VS Code 依赖，移除无关 npm 风险面；
  8. Docker 与 SSH 测试使用临时资源并确保 finally 清理。

测试迁移 ​

测试按能力迁移，不按文件数量虚假达标：

  1. 先迁移 23 个 pagent v4 专属测试并将 import 改为 ElectroMind；
  2. 迁移 app 测试中与 REPL、配置、审批、渲染和清理有关的有效行为；
  3. 删除只验证 pagent 品牌、旧 CLI 或旧路径兼容的断言；
  4. 新增产品身份、ElectroMind 路径、配置、密钥卫生和包边界测试；
  5. 新增 Local Sandbox 与 fixture Skill 集成测试；
  6. 新增 Docker 和 SSH 可选集成测试；
  7. 新增“源码和运行时不出现可 import pagent package”的检查。

每个迁移提交都必须满足 ruff、对应测试和 git diff --check。最终执行完整测试、分支 覆盖率和构建验证。覆盖率初始门槛不得低于迁移前实测的 78%；排除项必须逐项说明， 不能为了通过门槛排除核心 loop、审批或路径代码。

当前未提交工作树的处理 ​

当前工作树包含按旧“外部 pagent 薄产品”方案产生的大量未提交删除和新增。实施时：

  1. 先记录 git status 和完整 diff 清单；
  2. 创建专用整改分支，保留现有未提交内容；
  3. 复用其中正确的 Containerfile、Skill fixture 和密钥测试；
  4. 替换非 package pyproject、pagent.example.toml 和直接依赖 pagent 的测试；
  5. 从已确认的 Git commit 读取 pagent v4 源码，迁入新目录；
  6. 不使用 reset --hard、checkout -- 或破坏性清理；
  7. 每次提交只暂存明确列出的整改文件。

实施阶段 ​

阶段 0：安全与基线 ​

  • 轮换 Key；
  • 建立分支和来源记录；
  • 固化原 pagent v4 测试基线；
  • 确认旧工作树哪些内容复用。

阶段 1：行为等价内核迁入 ​

  • 迁移 core、conversation、threads、sandbox、skills、runtime、tools、adapters、trace；
  • 机械改写 import；
  • 迁移对应测试；
  • 保持 Agent 行为不变。

阶段 2：ElectroMind 产品化 ​

  • 建立 app、CLI、配置、状态路径和产品文案；
  • 建立 README、Makefile、Containerfile 和 CI；
  • 删除旧 pagent 包、文档、编辑器和发布资产。

阶段 3：边界与安全收尾 ​

  • 建立 facade 和依赖边界测试；
  • 完成密钥、依赖和镜像审计；
  • 运行 Local/Docker/SSH 验证；
  • 整理 Git remote 和产品版本。

后续里程碑：面向 ai2-kit 的强 Agent ​

以下能力不与基础迁移混做，但按顺序进入产品路线：

  1. 上下文压缩与 token budget；
  2. checkpoint、崩溃恢复和可恢复任务状态；
  3. HPC JobExecutor 与 Slurm backend；
  4. ai2-kit 训练 Skill 与领域镜像；
  5. 并行工具调度和资源配额；
  6. 更细粒度审批与审计日志；
  7. 可选的子 Agent/任务图编排。

Git 与发布 ​

现有 pagent remote 在整改完成后重命名为 upstream，用于来源追踪。用户提供新的 ElectroMind 仓库 URL 后再添加 origin。不得将继承的 pagent tags 推送到产品仓库； ElectroMind 从 v0.1.0 开始独立版本。

暂时保留既有 Git 历史，不做 history rewrite。未来若要建立全新产品历史，必须另行 设计可审计的导出流程。

验证命令 ​

最终标准检查至少包含：

bash
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run pytest
uv run pytest --cov=electromind --cov-branch --cov-fail-under=78
uv run electromind --help
uv run electromind version
uv run electromind doctor --config electromind.example.toml
uv build
uv run pip-audit

Docker 与 SSH 通过单独标记执行；正式 release check 必须包含 Docker。真实 LLM E2E 使用显式开关和用户环境 Key，不进入默认离线测试。

完成标准 ​

以下条件全部满足才算基础整改完成：

  1. ElectroMind 是可安装、可运行和可独立发布的产品。
  2. 仓库不依赖或提供 pagent/pagentv4 Python 包与旧 CLI。
  3. 派生内核源码位于 src/electromind，来源由 NOTICE 精确记录。
  4. 迁移后的内核测试覆盖原 v4 的 core、runtime、conversation、thread、Skill、 Sandbox、tool hooks、inbound 和 trace 行为。
  5. CLI、配置、状态路径、日志和错误全部使用 ElectroMind 身份。
  6. .pagent、PAGENT_HOME 和 pagent.toml 不被读取或创建。
  7. Local 与 Docker Sandbox、Skill 安装、审批、取消和资源关闭验证通过。
  8. jobs protocol 已预留，但基础整改不谎称已支持真实 Slurm。
  9. 配置模板无 Key，旧 Key 已撤销，依赖和密钥审计通过。
  10. 完整测试、分支覆盖率、构建和 release checks 通过。
  11. 用户能够只通过 README 和 electromind 命令完成安装、诊断和启动。
  12. 最终提交不包含用户本地配置、临时资源或无关工作树变更。
